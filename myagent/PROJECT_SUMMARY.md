# 트레이딩 에이전트 프로젝트 — 최종 기록

**기간:** 2026년 9월
**결론:** 일곱 가지 능동 매매 접근 전부 매수보유·균등 리밸런싱을 이기지 못함
**남은 자산:** 검증 하네스, 리스크 엔진, 실증 기록

---

## 1. 어디서 시작해서 어디로 왔나

**처음 목표:** 손절과 매매 시점을 정확히 예측하는 트레이딩 에이전트

**중간 수정:** 예측 정확도가 아니라 손실 통제의 일관성으로 목표 이동

**최종 결론:** 타이밍 기반 초과수익의 증거를 찾지 못함. 분산 보유 + 주기적
리밸런싱이 일곱 번의 비교에서 모두 우위

이 이동 자체가 프로젝트의 성과다. "안 된다"를 남의 말이 아니라 본인 데이터로
확인했고, 그 과정에서 앞으로 어떤 주장이든 검증할 도구를 갖췄다.

|---|---|---|
| 시계열 모멘텀 (55일 신고가 돌파) | **기각** | 초과R 전 구간 음수, 5봉 t=−4.79 |
| 시계열 평균회귀 (RSI3<15, 200MA 위) | **기각** | 초과R +0.165R (t=3.47) 유의하나 walk-forward 미달 |
| 무작위 진입 + 리스크 엔진 | 참고 | +0.126R / +6.51% |
| 매수 후 보유 | **최고** | +25.89% (walk-forward 구간 평균) |

## 3. 만든 것

### 리스크 엔진 (`risk/`)

| 파일 | 내용 |
|---|---|
| `indicators.py` | ATR (Wilder). 갭 반영 위해 전일 종가 사용 |
| `rules.py` | 손절가·포지션 사이징·시간 손절·추적 손절 |
| `portfolio.py` | 포지션·현금·평가, 서킷 브레이커 |

**핵심 공식:** 수량 = (계좌 × 0.5%) ÷ 손절폭
손절폭이 넓으면 수량이 자동으로 줄어든다. 이 한 줄이 계좌를 지킨다.

**확정 파라미터** (`configs.py`, 계좌 100만원 기준)
- `risk_per_trade` 0.5% — 종목당 비중 12.5% × 8종목 = 100%로 맞물림
- `atr_stop_multiple` 2.0 / `reward_risk_ratio` 2.5
- `max_drawdown_halt` 10% — 8종목 동시 손절(4%)의 2.5배
- `allow_fractional` **True (필수)** — 종목당 $87이라 정수 주식으론 거래 불가
- `time_stop_bars` 10 (잠정 — 시간축 무효 판정으로 확정 못 함)

### 검증 하네스 (`eval/`, `cycle.py`, 패치 1~5)

| 도구 | 무엇을 잡는가 |
|---|---|
| 시점 봉인 (`data/contract.py`) | 미래 봉 접근 시 `LookaheadError` 발생 |
| 단일 실행 경로 (`cycle.py`) | 백테스트·페이퍼·라이브가 같은 코드. t봉 판단 → t+1봉 시가 체결 |
| 무작위 기준선 | 출구 로직이 만든 수익을 신호의 공로로 착각하는 것 |
| MAE/MFE 측정 | 시간 손절값의 근거 |
| 시간축 유효성 (탄력성) | 캘리브레이션이 애초에 가능한지 |
| 클러스터 부트스트랩 | 중첩·상관된 표본으로 t값이 부풀려지는 것 |
| 다중검정 보정 | 여러 번 던져서 나온 우연을 발견으로 착각하는 것 |
| 생존편향 대조 (ETF) | 살아남은 종목만 테스트하는 것 |
| train 기반 파라미터 도출 | 출구 파라미터 과적합 |
| 회귀 테스트 (14항목) | 백테스터 자체의 결함 |

### 배분 백테스터 (`allocation.py`)

거래 단위가 아닌 비중 단위. 항상 100% 투자 상태를 유지하며 신호는
"무엇을 얼마나"만 결정한다.

### 데이터 로더

- `data/contract.py` — yfinance (미국 주식)
- `data/crypto.py` — ccxt (크립토, 4h/1d)
- `data/onchain.py` — Coin Metrics 커뮤니티 API (온체인, 무료·무키)

## 4. 잡아낸 버그와 방법론적 오류

프로젝트 진행 중 **내 코드와 판단에서** 발견한 것들. 같은 실수를 반복하지 않기 위해 기록한다.

| # | 문제 | 영향 |
|---|---|---|
| 1 | `gross_exposure`가 존재하지 않는 속성 참조 | 포지션 보유 시 크래시 (잠복) |
| 2 | 종가로 계획하고 시가에 체결 | 시가 +5% 갭에서 실제 위험이 의도의 **2.25배** |
| 3 | 추적 손절 청산이 전부 `stop_loss`로 기록 | 손절 247건 중 132건이 실제로는 이익 청산 |
| 4 | 시간축 판정을 "비율 편차"로 | 노이즈를 수렴으로 오인, momentum 오통과 |
| 5 | 기준선을 무작위로만 설정 | 정작 넘어야 할 상대는 균등 방치였음 (ETF 검사에서 발각) |
| 6 | 기준선 표본 799건 (신호는 5000건) | 오차가 기준선에서 지배됨 |

**5번이 가장 뼈아프다.** 무작위 5개를 이기는 건 쉬웠다(크립토 무작위 중앙값
−56.9%). 진짜 상대는 아무것도 안 하는 균등 방치였고, 그걸 늦게 알았다.

## 5. 배운 것

**신호에 엣지가 없어서가 아니라, 엣지가 있어도 시장 수익률에 못 미친다.**
meanrev는 여러 검정을 통과했다. 그런데 매매하는 동안 시장에 노출되지 않은
시간의 기회비용이 작은 엣지를 압도했다.

**"통과"가 나오면 축하하기 전에 왜 통과했는지 의심해야 한다.**
합성 데이터에서 두 신호 다 무효로 나와 판정 기준의 결함이 안 드러났다.
실데이터에서 momentum이 통과하는 걸 보고서야 기준이 틀렸다는 걸 알았다.

**파라미터 민감도 100%는 강건성의 증거가 아닐 수 있다.**
18/18 조합 전부 통과했지만, 이기고 있던 대상이 나쁜 대조군이었을 뿐이다.

**답이 대조군 안에 있었다.**
마지막 실험에서 온체인 지표를 하나도 안 쓴 균등 리밸런싱이 1위였다.

## 6. 시중 정보를 거를 때 물어볼 여섯 가지

1. 무작위 진입 기준선과 비교했나?
2. **매수 후 보유와 비교했나?** (빼놓은 건 거의 항상 의도적)
3. out-of-sample인가?
4. 거래비용을 넣었나?
5. 유니버스가 어떻게 정해졌나? (오늘의 우량주면 생존 편향)
6. 몇 번 시도해서 나온 결과인가? (다중검정 보정 가능 여부)

## 7. 다시 시작한다면 어디서부터

**하지 말 것**
- 더 정교한 기술적 지표 — 같은 데이터에서 같은 이유로 실패
- 더 큰 LLM, 더 많은 에이전트 — 정보 없는 곳에서 추론을 늘리면 노이즈만 증가
- 미국 대형주·메이저 크립토 일간봉 — 가장 효율적인 두 구석
- 파라미터를 바꿔가며 통과할 때까지 돌리기

**아직 안 해본 것**
- 경쟁이 적은 구석 (소형주, 예측 시장 등) — 100만원이 강점이 되는 유일한 영역.
  단 데이터 품질과 유동성 제약 반영이 관문
- 예측이 아니라 구조를 사는 것 (유동성 공급, 리스크 프리미엄 수취) — 꼬리 위험 큼
- LLM 지뢰 회피 (실적 발표·소송·회계 이슈 감지) — 수익이 아니라 손실 분포 개선 목표

**바로 할 수 있는 것**
- 실행 품질 개선 (세금·수수료·환전·리밸런싱) — 시장을 이길 필요 없고 확률 100%로 실현

## 9. 남은 한계

- **생존 편향이 완전히 제거되지 않았다.** ETF 유니버스도 청산된 ETF는 빠져 있다.
- **시점 봉인이 엄밀하지 않다.** yfinance 수정주가는 소급 변경되고,
  온체인 지표도 재계산되는 경우가 있다.
- **표본 기간이 짧다.** 크립토는 최대 6년, 대부분 강세장이었다.
- **검증한 것은 이 유니버스·이 기간에 대한 것**이다. 다른 조건에서
  다른 결과가 나올 수 있다.

이 기록은 투자 조언이 아니며, 특정 전략의 성과를 보장하지 않는다.
